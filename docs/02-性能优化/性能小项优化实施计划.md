## 1. A1 AcCmObject.set 无变更快速路径（common）

- 现状：`packages/common/src/AcCmObject.ts:147-231`——每次 set 无条件做 session 首写全属性 clone（:180）、两次深度 isEqual（:191-192）、`attrs = {}` 字面量（:166）。解析期每实体 4-6 次 set，其中 `ownerId` 重设（`AcDbBlockTableRecord.ts:423`）常为同值。
- 方案：
  1. 单键 set 且 `!unset && attributes[key] === val` 提前返回（引用相等蕴含 isEqual 成立；changed/prev 语义经推演保持不变）；对象形式全键预检。
  2. 循环内 `current[attr] === val && !unset` 短路，跳过 current 侧 isEqual 与写回（prev 侧 isEqual 保留）。
  3. `changes` 数组延迟创建。
  4. 子项（决策门）：`parseInt(handle,16)`（`AcDbDatabase.ts:1182`）每实体解析一次并缓存数值；若语义边界复杂则放弃并记录。
- 回归：`common/__tests__/AcCmObject.spec.ts`、`data-model/__tests__/AcDbObject.spec.ts`、`AcDbDatabaseTransactionManager.spec.ts`。

## 2. A2 实体 dxfIn 临时对象消除（data-model）

- 现状：`AcDbLine.ts:469-533`（~7 次分配/实体）、`AcDbCircle.ts:533-549`、`AcDbArc.ts:731-756`（各 ~6）、`AcDbPolyline.ts:769-877`（顶点数+1）。
- 方案：`AcGeOcsUtil` 原地变体 `acgeTransformOcsPointToWcsInto(out, point, normal)` + +Z 恒等短路；`new AcGeVector3d(nx,ny,nz)` → `this.normal.set(...)` + lengthSq 守卫原地 normalize；LWPOLYLINE `flushVertex` 复用 scratch 点。
- 回归：`AcDbArc.spec.ts:316-378`（OCS/-Z 挤出 dxfIn）、三夹具差分。

## 3. A3 实体工厂默认几何消除（data-model）

- 现状：`AcDbDxfEntityFactory.ts:44-135` 为 LINE/CIRCLE/ARC/ELLIPSE/SPLINE 构造即被 dxfIn 丢弃的默认几何（SPLINE 用 4 个假控制点建整条样条；ELLIPSE 整个 `AcGeEllipseArc3d` 被替换）。
- 方案：各实体类惰性 `_geo`（getter 按需初始化）；工厂走不建几何的构造路径；dxfIn 由暂存标量在末尾一次性建几何。dxfIn 完成前任何读者不得触发半初始化实体。
- 契约变更：`AcDbArc.spec.ts:367` 记录的「工厂默认 +Z refVec」契约测试随新契约同步更新（改动清单内明确）。
- 回归：data-model 全量、`AcDbDxfPhase3to5.spec.ts`、三夹具差分。

## 4. A4 AcDbRenderingCache LRU（data-model）

- 现状：`src/misc/AcDbRenderingCache.ts:133-134` `_blocks: Map`，仅文档关闭时 clear。
- 方案：仿 `AcTrMTextGlyphCache`（插入序 LRU、命中 touch、条目数+估算字节双预算，默认 512 条/64MiB，静态可配）。
- **安全规则**：逐出模板若 duck-type `isCompacted === true`（与场景克隆共享 BufferGeometry，见 `AcTrGroup.ts:509-519` 隐患）不 dispose，转入 `_retiredList` 待 `clear()` 统一 dispose；非 compacted 逐出即 dispose。`clear()` 语义权威不变。
- 回归：`AcDbRenderingCache.spec.ts`（dispose-on-clear 断言保持）+ 新增 LRU 测试。

## 5. B1 lineDistance 按需计算（three-renderer）

- 现状：`AcTrBatchedLine.ts:309-310` add 时无条件 `computeSegmentLineDistances`；`:453-455` setGeometryAt 补齐。lineDistance 使每线批顶点内存 +25%，仅 `resolveDashMode === 'line'` 的虚线高亮消费。
- 方案：批创建按材质 dash 模式决定惰性（`'none'` 跳过）；首次高亮安装时按需为全槽计算并写入打包缓冲（addUpdateRange）；材质换绑（`AcTrBatchedGroup.updateMaterial`/`rebindBatchedMaterialsForLayer`）重置就绪标记；模块开关默认开。AcTrBatchedLine2 保持现状。
- 回归：`AcTrBatchedLineDistance.spec.ts`、`AcTrBatchHighlightShaders.spec.ts` + 新增惰性测试。

## 6. B2 高亮掩码 GPU 局部上传（three-renderer）

- 现状：`AcTrBatchHighlightState.ts:240-299`——CPU 侧已脏窗口重写（M4-2），GPU 侧每次整张 `needsUpdate`（three 0.172 DataTexture 无 update-range API）。
- 方案：现有纹理分支记录待上传像素区；onBeforeRender 路径（有 renderer）经 `renderer.getContext()` + `renderer.properties.get(texture).__webglTexture` 执行 `gl.texSubImage2D`；无 renderer（microtask flush）或纹理未建 → 回退 `needsUpdate` 整张上传；布局变化仍整张重建。跨行脏区回退整张。开关默认开。
- 回归：`AcTrBatchHighlightState.spec.ts` CPU 断言保持；GL 调用抽独立函数用假 renderer spy。

## 7. B3 包围球脏同步等值跳过（three-renderer）

- 核实结论：逐槽 bbox 已懒缓存，全槽循环只做廉价 Box3 并集；真实浪费是「顶点改回相同范围仍置脏 → 下一帧全量重并集 + 一帧未剔除绘制」。
- 方案：`applyGeometryAt` 先算入槽几何新 box 与缓存比较，等值（epsilon）→ 不置 null、不 `invalidateFrustumBounds`；不等 → 现行为。删除路径（optimize 全量重算）与「culling 开启期间球体不得收缩」不变量不动。
- 回归：`AcTrFrustumCulling.spec.ts` + 新增等值跳过用例。

基线存档 → A1 → A2 → A3 → A4（每项后：包 jest + tsc；A 阶段末：三夹具 bench-parse 差分）
        → B1 → B2 → B3（每项后：three-renderer jest + tsc；B 阶段末：cad-simple-viewer 全量）
        → 文档状态回填（优化计划/性能优化总结/框选分析）→ 不 commit
