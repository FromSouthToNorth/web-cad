## 一、性能瓶颈的根源（现状）

### 1.1 解析层

- **数据规模锚点**：95MB / 389,328 实体的 GBK 矿图，坐标为八位数字的高斯投影值。
- **Worker 化只覆盖词法层**：pair 流解析（字节 → 类型化组码对）是唯一的 CPU 密集纯计算环节，已移入 Worker；其后的 `AcDbDxfDocumentReader` / 实体 `dxfIn` 直接写 `AcDbDatabase` 对象图、不可结构化克隆，仍留在主线程。大图纸打开时主线程仍承担数秒语义构建与实体 flush。
- **残余热点**（第二版 §1.3）：值行仍逐行 `text.slice` + `Number()`（10 万实体约 80 万次分配，`AcDbDxfPairReader.ts:206-242, 447-460`）；pair 对象无池化；实体 dxfIn 临时对象 + `commitEntity` 开销；让门仍用 `requestAnimationFrame`（后台标签页被节流至 1fps，后台打开大图显著变慢）。
- **编码判定风险**：UTF-8 字节 + 陈旧头（AC1015/ANSI_936）的图纸会被按 GBK 误解码，建议增加合法 UTF-8 字节序列嗅探兜底。
- **历史根因（已修）**：该文件 `$HANDSEED = FFFFF10000002B` 超过 `Number.MAX_SAFE_INTEGER`，浮点自增结果不变导致 `generateUniqueHandle` 死循环——文件打开在 16% 永久卡死，已用 BigInt 计数修复。

### 1.2 渲染层

- **一次性构建饿死 rAF**（旧结论，已修）：解析完一次性构建全部实体渲染对象，期间 rAF 饥饿，浏览器实测 12s+ 无帧。
- **视锥剔除**：批级已实现；各批容器构造函数仍初始化 `frustumCulled = false`（`AcTrBatchedLine.ts:101` 等），几何脏期间保守全画属正确语义；**槽级剔除未做**，散布全图的线/面仍产生大量批次容器。
- **大坐标精度**：批容器本身会按批原点 rebase 顶点（`RTE_REBASE_THRESHOLD = 1e6` 分裂，`AcTrBatchedGroup.ts:1915`），普通线/圆弧/文字/点在大坐标下精确；精度崩坏只在少数构建路径——`THREE.ShapeGeometry` 直接对 WCS 点三角化（图案/实心填充/图像）与上游 `AcDbFace`/`AcDb3dSolid`/ACIS 线框的 Float32 打包，量化发生在 rebase 之前，放大后三角形退化、填充塌缩，表现为图层「消失」。另：相机 near/far 固定 0.1/1000 截断了 Z 高达 19.7M 的实体。
- **剩余状态更新热点**（第二版 §2.2）：可见性切换整缓冲重传（`AcTrIndexedBatchDrawVisibilityStrategy.ts:25-52`）；optimize 尾部清零段裸 `needsUpdate`；MTEXT 逐实体 worker 往返、无内容级字形缓存；高亮掩码整张重建（`AcTrBatchHighlightState.ts:194-230`）；free-list 每次 reserve `sort + shift`（大删后连续新增可退化 O(n²)）；转换期 shell dispose 连坐共享材质；缓存无 LRU。

### 1.3 选择、标记与删除层（旧版薄弱处，本次补全）

- **框选命中**：RBush 层次索引（`AcTrRBushSpatialIndex.ts` + `AcTrHierarchicalSpatialIndex.ts`）+ 每槽 drawRange 射线，线性复杂度（第二版 §2.3 已确认）。
- **标记**：框选大量实体时逐实体查询 grip 点曾是框选耗时主导。`AcEdSelectionVertexMarkers.ts:29-36` 引入 `MAX_MARKER_ENTITIES = 1000` 上限（对齐 AutoCAD GRIPOBJLIMIT 行为）：超出直接跳过逐实体标记；grip 点缓存复用（hover 变化只重查单个实体）；单点拾取只标最近实体，其余选中实体仅保留虚线反馈。
- **删除**：逐实体 `erase` 会反复重扫 owner record 的实体数组。`AcApEntityService.eraseEntities`（`AcApEntityService.ts:148-167`）改为单次 `AcDbBlockTable.removeEntity` 扫一遍 + 单次批量 erased 通知；批容器侧压缩与高亮掩码上传经 microtask 合并（`AcTrBatchedGroup.ts:282-292, 1297-1311`），同一轮删除的每个批次只压实一次。

## 二、已实施的优化

### 2.1 解析层

- **词法解析移入 Web Worker**：`AcDbDxfPairWire.ts` SoA 线格式（`codes: Int32Array` / `types: Uint8Array` / `numbers: Float64Array` / 去重字符串表 / long 十进制字符串 / binary 侧数组），worker 内 `acdbDrainDxfPairs` 抽干、主线程 `acdbMakeDxfPairArrayReader` 回放同一 pair 流；`AcDbDxfParserWorker.ts` + `vite.config.worker.ts` 产出 `dist/dxf-parser-worker.js`；`AcDbNativeDxfConverter` 默认 `useWorker: true`，worker 不可用（Node、bundle 缺失、任务失败）自动回退主线程流式解析；typed array 零拷贝 transfer 回传。进度映射：词法 1–10%、主线程语义构建 10–18%、ENTITY 20–98%。
- **窗口化解码**：64KB 行对齐窗口化 reader 覆盖 UTF-8/GBK/Big5/Shift-JIS/EUC-KR/单字节页；多字节序列内不可能出现 0x0A/0x0D，窗口行对齐安全。仅 UTF-16 家族与 `TextDecoder` 不认识的标签走全量解码。
- **M1 零分配热路径**（`AcDbDxfPairReader.ts` / `AcDbDxfFiler.ts`）：char 级 group code 扫描 `acdbReadDxfCodeFromChars`、数值解析不再先 trim、filer 去 `pairToTypedValue` 包装；标准夹具解析中位数改善约 5–12%。
- **BigInt handle 修复**（`AcDbDatabase._maxHandleBig`）：`$HANDSEED` 超安全整数后切换 BigInt 计数。
- **基准**：UTF-8 混合夹具（10 万实体、8.5MB）843ms / 峰值堆 237MB；GBK 矿图 4.5s（best of 3）、窗口化后 GBK 峰值 ~720MB。

### 2.2 渲染层

- **渐进式渲染默认开启**（M2）：`MlCadViewer.vue`、`App.vue`、`AcApDocManager.setOptions` 两分支默认 progressive；CLI 无头导出显式关闭（不画帧，无需让出）。浏览器实测：关闭时 rAF 饥饿 12s+，开启后最大帧间隔 91ms；`bench/progressive.html` + `progressive.ts` 独立 A/B 基准页。
- **批级视锥剔除**：`AcTrBatchedMixin.ts:715-970` 在 `onBeforeRender` 做脏同步——几何变更后首帧 `computeBoundingSphere` 计算聚合包围球再打开 `frustumCulled`；全局开关 `_batchFrustumCullingEnabled` 默认 true（`:782`）；新增 `AcTrFrustumCulling.spec.ts`。
- **构建期原点平移 + 双精度传递**：`AcTrPolygon`/`AcTrImage` 先减 WCS bbox 中心锚点再三角化、`mesh.position = anchor`；`AcTrLineGeometryBuilder.buildAreaGeometry` 计入 `mesh.position` 避免二次 rebase 重新放大坐标；`AcDbFace`/`AcDb3dSolid`/ACIS 线框缓冲 Float32→Float64，rebase 前不再量化；`AcTrBaseView.updateCameraDepthRange` 抬升相机并覆盖 19.7M 深度范围。验证：`AcTrOriginShift.spec.ts` 8 例 + 2300 实体 39M 坐标 fixture 端到端（全部入批、滚轮缩放后帧持续推进 maxFrameGap 90ms）。
- **GPU 侧手段（修正表述）**：索引几何合批（`AcTrBatchedLine/Mesh/Point/Line2` + `AcTrBatchedGroup`，按材质与批原点分裂容器）；drawRange 槽级可见性策略（`AcTrIndexedBatchDrawVisibilityStrategy` 等）；自定义高亮着色器（`AcTrBatchHighlightShaders.ts`）。**未使用 InstancedMesh 实例化渲染。**

### 2.3 交互层

- **选择/标记优化**（`4bbe801 feat: 框选选中对象日志打印与大量数据选择/标记性能优化`）：`AcEdSelectionVertexMarkers.ts` 标记上限 + grip 点缓存；`AcEdGripManager.ts`、`AcEdBaseView.ts`、`AcTrLayout.ts`、`AcTrView2d.ts` 联动；附 `bench/verify-click-select.cjs` 验证脚本。
- **批量删除优化**（`fed11a2 perf: 框选大量对象删除性能优化,修复卡顿崩溃`）：`AcApEntityService.ts` 单遍删除 + 单次通知；`AcTrBatchedGroup.ts` microtask 合并压缩与掩码上传；测试 `AcTrBatchedGroupBulkRemove.spec.ts`、`AcApEntityService.spec.ts`。
- **模块化**：`AcEdSelectionSet.ts`（选择集）、`useSelectionSet.ts`（Vue 组合式封装）；空间索引层 `spatialIndex/`（RBush + 层次索引）。
- **验证脚本体系**（`cad-viewer-example/bench/`）：`verify-box-select.cjs`、`verify-click-select.cjs`、`verify-select-combos.cjs`、`verify-app-select.cjs`、`verify-multi-cluster.cjs`、`verify-deep-probe.cjs` 等。
- **已确认无问题**（第二版 §2.3，不重复优化）：交互缩放/平移不触发批次重建（rebase 仅在入批时一次）；框选命中与批量删除均为线性复杂度。

### 2.4 相邻修复（直接影响大图纸打开与框选体验）

- **进度「100% → 0% 重来」**：三个机制叠加（两个进度域共用同一数字、URL 打开时 FETCH_FILE→CONVERSION 峰值归零、打开失败后 regen 重开），根因与修复方向见《渲染与解析性能瓶颈分析》§〇。
- **LWDISPLAY 中途 regen**（实测主因，已修复）：图纸头 `$LWDISPLAY: 1` 在解析途中触发 `AcApContext` 监听器 `view.clear() + db.regen()`（`AcApContext.ts:119-129`），重放整轮进度导致 100%→20~40% 回跳，并提前把数万实体推入视图转换纯白耗主线程。修复：场景无内容时只同步标志位、不重建（`AcTrScene.hasContent()` 早退）；测试 `AcApContextLwDisplay.spec.ts` 3 例；修复后 PARSE 阶段 9.4s→6.0s（无争用）。

## 四、总结与建议

「异步词法解析 + 渐进式渲染 + 合批与批级视锥剔除 + 线性选择算法」是当前处理大型 CAD 图纸的有效组合。
旧版归纳的四个方向（异步解析、渐进式渲染、GPU 加速、算法优化）方向正确，但表述需按上文修订：解析只
Worker 化了词法层；视锥剔除是批级、槽级仍缺；GPU 加速靠索引合批与自定义着色器而非实例化；大坐标精度
问题已通过构建期原点平移解决。

按收益排序的后续建议（引自第二版 §四）：

1. 修进度数字回退（drain 期间数字保持隐藏或单调不减）——消除「100%→0% 重来」假象；
2. 进度全局权重分段 + 去掉 FETCH_FILE→CONVERSION 峰值归零；
3. 值行 char 级数值扫描——解析再降 0.5–1s、GC 压力大减；
4. UTF-8 有效性嗅探兜底——修「UTF-8 字节 + 陈旧头」图纸乱码；
5. MTEXT 内容级字形缓存 + 往返合并——多文字图纸打开提速、overlay 提前结束；
6. 可见性切换 / optimize 尾部 `addUpdateRange`——图层开关、批量删除不再整缓冲重传；
7. pair 池化、lineStyle 缓存引用、free-list 去排序；
8. 高亮掩码局部更新、让门换 postTask/setTimeout。
