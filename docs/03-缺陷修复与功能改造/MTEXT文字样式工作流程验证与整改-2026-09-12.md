# MTEXT「注释→文字」文字样式工作流程验证与整改（2026-09-12）

> 触发：以多智能体（Agent Teams）协同方式，验证用户工作流程
> **「注释 → 文字 → 框选 → 输入中文 → 修改设置文字样式 → 点『关闭』提交」** 是否正常，并整改。
>
> 结论：**修复前该流程在「修改设置文字样式」这一步是断的**——用户在文字编辑器里改了文字样式，
> 下拉框马上弹回旧值、已成文字不变、提交后实体仍然挂着旧样式。已修复 3 处缺陷 + 2 处一致性
> 缺口，并新增浏览器级回归测试 5 条（修复前 3 条红灯）。

## 2. 根因

### 2.1 落库时用的是「打开编辑器之前」的样式快照（阻断级）

`AcApMTextCmd.execute()` 在**打开内联编辑器之前**解析文字样式记录（`resolveAt(database.textstyle)`），
编辑结束后又用同一份快照写 `mtext.styleName`。而功能区的「文字样式」控件是在编辑器**打开期间**
把 `$TEXTSTYLE` 改成用户选择的值，于是：画布上的当前样式变了、新实体却仍挂旧样式。

### 2.2 文字样式下拉不回显（阻断级 UI）

`useMTextRibbon` 里的 `textStyleNames` / `currentTextStyle` 等 `computed` 只读
`AcApDocManager.instance`（普通单例，不是响应式对象），**没有任何响应式依赖** → 首次求值后永久缓存：
控件绑定的是缓存值，用户选完新样式后单选框立刻弹回 `Standard`，看起来像「点了没反应」；
换图纸后样式/字体/字高列表也不会刷新。

### 2.3 无选区时样式只作用于「之后输入的字」（行为级）

库的 `setCurrentFormat()` 在选区折叠时只改**插入格式**，即只影响之后敲入的字符，已输入的
「中文测试」不会变。用户「先打字、再选样式」时因此完全看不到变化。

### 2.4 取消（Esc）不回滚 `$TEXTSTYLE`（契约级）

功能区控件直接写 `db.textstyle`，而命令在取消路径上正常 return（事务照常提交）
→ 按 Esc 取消后图纸的当前文字样式被留在了新值，违反《修复契约》「取消：必须零数据库写入」。

### 2.5 双击就地编辑路径不采纳样式（一致性问题）

`AcTrView2d.editMTextEntity()` 只回写 location/contents/width/height/lineSpacing/attachment，
从不写 `styleName`。同一动作（在编辑器里选样式）在「新建」和「就地编辑」两条路径上结论不同。

## 3.1 用户提供的最小复现图（`Untitled.dxf`）说明了什么

用户随后提供了一个 4KB 的复现图（已作为夹具 `e2e/fixtures/mtext-single-style.dxf` 入库），复核结论：

- **该图只有 1 个文字样式**（`Standard`，字体 `SimKai`，`$TEXTSTYLE=Standard`），ENTITIES 里 1 个
  MTEXT（内容 `{\A1;\c0;\fSimKai|b0|i0;\H56.83;你好}`，DXF 7 = `Standard`）。
  因此「文字样式」下拉里**根本没有第二个样式可选**——此时「改样式后提交，实体仍是旧样式」是必然的，
  不是提交链路的问题（用同一流程跑用户那张 107MB 真实图纸，选 `HZ` 后实体 `styleName` 实测为 `HZ`）。
- 该图里能真正改变外观的只剩**字体**控件，而它当时（a）无选区时只影响之后输入的字，
  （b）候选列表几乎为空：实测 `AcApDocManager.instance.avaiableFonts === []`，下拉只有
  `["SimKai", "Arial"]`——因为 `avaiableFonts` 只会被 `AcApFontLoader` 的目录拉取填充，
  而正文按需加载走的是 mtext-renderer 自己的 FontManager，从不经过它。

对应整改：第 7 项覆盖 (a)；字体目录 (b) 已由并行的字体预加载改造覆盖
（`useAntdCadShell` 打开 `preloadDefaultFonts` / `preloadDrawingFonts`，`App.vue` 交还默认字体链），
本次未再重复实现。

## 3.2 为什么字高不再镜像

契约 D4.1 明确「字高的权威来源是 `AcDbMText.height`（DXF 40）；序列化时不写绝对 `\H`」，
并禁止「面板与内联码打架」。样式自带的字高属于**新建文字的缺省值**，
而本流程里字高已由框选高度决定（D1：显式动作优先），因此改样式时只改字体不改字高。
附带说明：旧代码里 `fixedTextHeight ?? lastHeight` 的 `??` 分支实际不可达
（`normalizeMTextNumber(0)` 返回 `0` 而不是 `null`/`undefined`），本次一并删除，避免它被误当成
「字高的第二个来源」。

## 4. 新增测试

**E2E** `cad-viewer-example/e2e/tests/mtext-style-workflow.spec.ts`（夹具 `mtext-two-styles.dxf`，
两个样式字体不同：`Standard=hztxt`、`HZ=simkai`，便于断言样式切换真的落到 payload）：

1. `the Text workflow commits the Chinese MTEXT with the style chosen while editing`
   —— 完整用户路径；断言下拉回显 `HZ`、提交后 `styleName==='HZ'`、`contents` 含 `中文测试` 且带
   新样式的字体 `\fsimkai`（证明"整段重排"真的生效）、`$TEXTSTYLE==='HZ'`。
2. `typing after the mid-edit style change appends to the same MTEXT`
   —— 改样式后继续输入必须**追加在原文之后**（同时守住「选区被留下 → 下一次按键覆盖全文」这条
   毁灭性回归），并断言两段的先后顺序。
3. `cancelling with Escape rolls the mid-edit style choice back`
   —— Esc 取消：不产生实体、`$TEXTSTYLE` 回到 `Standard`。
4. `the Chinese UI labels drive the same Text workflow`
   —— 中文界面（「文字」/「关闭」/中文提示）走通同一条路径（此前 E2E 从未覆盖中文语言包）。
5. `changing the font after typing restyles the text that is already there`
   —— 单样式图（`mtext-single-style.dxf`，即用户提供的最小复现）：打字后改**字体**，提交后的
   `contents` 必须带上新字体（`\f宋体|simsun`），实体的 DXF 7 仍为 `Standard`（字体是内联覆盖，
   不是新建文字样式）。这条同时验证了「字体目录预加载」与「整段作用域」两件事。
6. 上下文标签/面板回归沿用 `mtext-draw-accuracy.spec.ts:618` 的既有用例。

**单测**（修复前会红的那几条才是有效回归）：

- `cad-simple-viewer/__tests__/AcApMTextAccuracy.spec.ts`：编辑期间切换样式 → 实体取新样式；
  取消 → `$TEXTSTYLE` 回滚；提交被拒（空白内容）→ 同样回滚。
- `cad-simple-viewer/__tests__/AcEdMTextEditor.spec.ts`：桥的 `applyFormatToWholeText` 在折叠选区下
  `selectAll/clearSelection/moveTo(原光标)`，在真实选区下只走 `setCurrentFormat`；会话结束后桥方法被清理。
- `cad-simple-viewer/__tests__/AcEdMTextEditorLifecycle.spec.ts`：就地编辑采纳/不采纳/取消回滚样式。
- `cad-viewer-example/__tests__/mtextRibbon.spec.ts`：整段重排调用（样式 / 字体 / 字高 / 字符效果）、
  **不镜像任何样式字高**、无整段桥方法时回退、下拉值刷新、换图纸后样式列表重建。

## 6. 明确未做（后续）

1. `formatColorDisplay`（当前图层色）仍不随 `drawingRevision` 刷新，需要自己的失效源
   （`CLAYER` / 图层色变化）。字体目录由并行的字体预加载改造负责填充。
2. `contents` 被库写满 `\f`/`\H`/`\c` 内联码（审计 P2-8/P2-22）不在本次范围；因此「用同字体的两个
   样式互切」在**外观上**仍然看不出差别（DXF 7 已正确变化）——夹具因此特意让两个样式用不同字体。
3. 功能区折叠态 / 移动端 compact 下「关闭」按钮不可达（既有 UI 问题）。
4. 就地编辑路径没有浏览器级 E2E 覆盖（本次只在单测层覆盖），双击编辑 → 改样式 → 关闭 的端到端
   用例可作为下一批补强。
5. **行距落库为 0.3（契约 D2 要求新建为 1.0）**：用户提供的复现图里，新建 MTEXT 的 DXF 44 = `0.3`，
   而 `AcEdMTextEditor.defaultLineSpacingFactor` 是 `1.0`。命令写的是
   `result.lineSpacingFactor`，即 mtext-input-box 自己文档的默认值（0.3）；该库没有「打开时指定行距」
   的入参，因此需要在编辑器层补一个（或有意识地覆盖 0.3 的初值），本次未改以免影响就地编辑的
   「不得改写实体既有行距」语义。建议单独一轮处理并补 E2E。
