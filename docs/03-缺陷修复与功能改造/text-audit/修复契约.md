> 不得各自决定单位、下限、默认值或空值语义——报告已指出「多处各自解释」正是缺陷根因。
> 基线：`git 534da15` + 本次会话的审计产物。基线测试状态：Jest **2352 passed / 2 suites 既有失败**

## D1 字高（text height / DXF 组 40）

- **语义**：组 40 = **每行字符高度**（世界单位），不是文本框高度。
- **取值优先级**（新建 MTEXT，按"用户显式动作优先"排序）：
  1. **用户框选的高度** `|box.max.y − box.min.y|`——框选是本次操作中最明确的尺寸意图；
  2. 否则取**当前文字样式的固定字高**（`AcDbTextStyle.textSize`，即固定 `$TEXTSIZE`）；
  3. 否则退回屏幕折算值（`pixelsToWorldY(view, 24)`），保证字总是可读。
- **为什么样式 `priorSize`（`lastHeight`，DXF 组 42）不参与新建取值**：
  它是"上一次用过的字高"，不是固定字高。AutoCAD 默认图纸的 `$TEXTSIZE` 就是 `0.2`，
  若把它排在框选之前，一次 200×30 像素的框选会画出 0.2 图纸单位高的字（屏幕上几乎不可见）——
  实测该行为会让 E2E 像素判据只测到 15 个墨迹像素。故 `priorSize` **只作为样式的缺省展示值**，
  不参与新建实体的取值。
- **下限**：统一 `ACDB_MTEXT_MIN_HEIGHT = 1e-4`（世界单位）。
  **删除** `AcEdMTextEditor` 中的 `Math.max(1, textHeight)`——编辑器不得改写用户/样式给定的字高。
- **预览与落库同源**：编辑器拿到的 `textHeight` 与最终写入 `mtext.height` 必须是同一数值来源。

## D2 行距（lineSpacingFactor / DXF 组 44）

- **默认值 1.0**（相对单倍行距），与 DXF 语义一致。**删除** `AcEdMTextEditor.defaultLineSpacingFactor = 0.3`。
- **新建**：`AcDbMText` 构造默认 1.0，命令不得覆盖。
- **编辑**：不得改写实体既有 `lineSpacingFactor`；编辑期只读、提交时原值回写。
- **取消（Esc）**：必须零数据库写入。

## D3 宽度（width / DXF 组 41）

- **语义**：换行参考宽度（word-wrap max width）。**`0` 表示不折行（= 无限宽）**，不得替换为 `1e-4` 或 `Math.max(1, …)`。
- 编辑器内部若必须用有限宽度排版，该宽度**只用于编辑器自身布局**，不得回写到实体。
- 落库规则：用户框宽 `<= 0` 或 NaN 时写 `0`（不折行），否则写框宽。
- **禁止**在编辑既有 MTEXT 时把组 41 由 `0` 改成非 0。

## D4 内联格式码（contents）

- `contents` 中的 `\H`（绝对字高）与 `\c`（绝对颜色）会覆盖 DXF 40 与实体颜色。
- **ByLayer 颜色不得序列化进 contents**（图层色是解析结果，不是实体属性）。
- 字体/字高/对齐等格式码可以保留；但**改字号必须同步回写 `mtext.height`**，避免「面板与内联码打架」。
- `contents` 原样保留首尾空白与换行；空内容判断用 `trim()` 但**写库时写原串**。

### D4.1 字高与内联 `\H` 的落地细则（施工口径，避免歧义）

契约必须可执行，故明确如下：**字高的权威来源是 `AcDbMText.height`（DXF 40）；序列化时不写绝对 `\H`。**

- 编辑器序列化时，把「与实体当前字高相同」的 run 字高视为**默认值**，不输出 `\H`；
  仅当用户在同一实体内的不同 run 使用了**不同于实体字高**的字高时，才为该 run 输出 `\H`（相对覆盖，AutoCAD 语义）。
- 因此：改属性面板的「文字高度」→ 改 `mtext.height` → 渲染立即生效（不再被 `\H` 遮盖）；
  用户也可继续用编辑器给单个 run 设置特殊字号。
- 颜色同理：与实体/图层解析结果一致的 run 不输出 `\c`。

> 若实现发现「不输出 `\H`」会破坏编辑器自身的所见即所得预览，允许退让为
> 「输出 `\H` 但**在改 `mtext.height` 时同步重写所有等价 run 的 `\H`**」；
> 无论选哪条，验收标准相同：**改 `mtext.height` 后渲染必须变化**（见 L1/L2 验证）。

## D5 样式与图层

- 落库前**显式固化**：`mtext.styleName` 取当前文字样式记录的 `name`（非空）；
  `mtext.layer` 取 `database.clayer`。
- `styleName` 为空串时 `AcDbDxfFiler` 不得写出组 7；空串语义单独处理。

## D6 空值与空内容

- **新建**：`contents.trim()` 为空 → 不落库 + i18n 提示（不得静默 return）。
- **编辑**：提交为空串 → 拒绝并提示（不得把实体 `contents` 写成空串）；Esc 取消不算提交。
- `AcDbDxfFiler`：空字符串值**跳过该组码行**，不得写成字符 `0`（影响组 1/7/8 等）。
- 非正 `height`（<= 0）落库前拒绝并提示。

## D7 旋转与方向（rotation / directionVector）

- `rotation`（弧度）与 `direction`（单位向量）是同一自由度的两种表示，**必须双向同步**：
  - `set rotation(θ)` → `_direction = (cosθ, sinθ, 0)`；
  - `set direction(v)`（`v.lengthSq() > 0`）→ `_rotation = atan2(v.y, v.x)`。
- 零向量：`dxfIn` 遇到组 11/21/31 全 0 时 `_direction` 保持 `(1,0,0)`，不得产生 `(0,0,0)`
  （否则 Three 的 `angleTo` 返回 π/2，文字被额外旋转 90°）。
- `AcDbProxyGraphic` 传给 `AcGiMTextData.rotation` 的必须是**弧度**，删除 `* 180 / Math.PI`。

## D8 导出（SVG / PDF）

- 文字布局与画布**同源**：导出不得使用独立的逐字符估宽算法作为唯一依据。
- 宽度因子**只应用一次**（不得 `initialCtx` 与 `tspan transform` 各乘一次）。
- 不得无条件乘 `0.85`。
- `height <= 0` 的处理三处（SVG/three/HTML）必须一致：统一按样式 `fixedTextHeight` 回退；仍为 0 则不绘制并告警一次。
- 同名块导出的模板克隆必须**真深拷贝**（`fastDeepClone` 不得返回 `this`）。

## D9 事务与取消

- MTEXT 命令的落库必须包在 `AcEdCommand.trigger` 的 undo mark 内（现状已满足，勿破坏）。
- 编辑器必须可取消：暴露 `closeEditor(reason)`，并接入命令层 `cancelActive`。
- 文档切换（`openDocument`/`onBeforeOpenDocument`）前：取消活动命令 + 关闭编辑器。
- 编辑器单实例：`open()` 前若已有 `activeInputBox`，先结算它。

- 不改变既有无关节点的行为；每个修复必须能被某个测试/判据捕捉（新增或复用 L1/L2/L3/L4 设施）。
