## 新发现（不在原始审计 55 条内）

> 由用户侧另一份排查报告带入并经本仓独立复核确认。为不改动原有 55 条的编号与统计，单列于此。

### X-1 ✅ 已修复｜P1｜编辑 MTEXT 时打字，画面不重绘（用户表现为"输入不了文字"）

- **位置**：`cad-viewer/packages/cad-simple-viewer/src/editor/input/ui/AcEdMTextEditor.ts` 的 `onRenderFrame`
- **证据（本仓复核）**：原实现只 `mtextInputBox.update(); view.isHtmlDirty = true`，全文无 `view.isDirty`。
  而 `AcTrView2d` 对该标志的文档写明：`isDirty` = "WebGL scene needs to be re-rendered"，
  `isHtmlDirty` = "**Does not force a WebGL redraw**"（`AcTrView2d.ts:838-1001`）。
  MTEXT 字形画进 `view.internalScene`，因此只置 `isHtmlDirty` 永远不会把它们画出来——
  直到平移/缩放顺带置脏才"突然"出现。
- **影响**：`mtext` 命令拖框后打字看不到任何字；用户会认为是"文字工具输入不了"。
  这也解释了报告 §5.2 L4 记录的已知局限「**编辑期间画布不重绘**（探针在 Chrome/Edge 均确认）」——
  该局限正是本缺陷，**修复后应失效**；当时因此只能把 E2E 设计成「命令前空白 / 提交后出墨」的因果对照。
- **修复**：订阅 `change` / `cursorMove` / `selectionChange` 三个编辑器视觉事件，回调里置 `view.isDirty = true`；
  `cleanup()` 同步 `off`（在 `dispose()` 之前）。
- **取舍**：没有在 `onRenderFrame` 里无条件置 `isDirty`——那会让编辑器打开期间每帧全量重绘 WebGL，
  在大图纸上是明显性能回退；改按事件触发，只在真有视觉变化时重绘。
- **回归测试**：`AcEdMTextEditor.spec.ts` 新增「marks the WebGL scene dirty when the editor content changes」，
  覆盖三个事件各自置脏、以及关闭后不再置脏（监听已释放）。
  已做红灯验证：临时移除三个订阅后该用例失败（`Expected: true, Received: false`），确认非空测试。
- **未做**：中文 IME 组合键路径（`compositionstart/update/end`）未在本仓复测；真实大图纸上的重绘帧率未做基准。
