## 2. 冻结合同（全队遵守）

- **D1 单实例与取消**：同一时刻只有一个活动输入框；再次 `open()` 必须先让旧 Promise settle（绝不永久 pending）；取消路径 resolve `null` 且**不写数据库**。
- **D2 结果契约**：`height` = 字高（DXF 40，不得夹取）；`committedWidth` 的 `0` 必须原样保留（0 = 不换行）；`lineSpacingFactor` 缺省 `1.0`；`attachmentPoint` 语义 1..9。既有字段语义不变，只新增可选字段 `heightSource` / `committedHeight`。
- **D3 附着点**：编辑器侧校验 1..12 越界回退 TopLeft；命令侧落库继续夹取 1..9。
- **D4 空内容**：创建路径与双击编辑路径行为一致——trim 后判空、拒绝写库、给本地化提示。
- **D5 资源释放**：所有退出路径都清空 activeInputBox、detachFormatBridge、dispose 输入框、移除隐藏工具条宿主、解绑 renderFrame 与全部 `off(...)`、解绑 sysVarChanged。
- **D6 渲染侧遗留**：`_pendingGlyphKeys` 有界 + `clearDocumentState()`；字形缓存克隆体 box 随插入点重定位。
- **D7 i18n**：新增文案四个 locale 同步，key 静态引用。

## 3. 交付内容

### 3.1 编辑器生命周期（D1 / D5）

- 新增 `activeSession` 会话对象（`inputBox` / `settle` / `cancel` / `dispose` / `released` / `finished`），把"取消"与"提交"从库的单一 `close` 事件里分离出来。
- `open()` 首行回收上一个会话（`finishSession(previous, null)`），旧 Promise 必定 settle。
- 新增静态 `getActiveEditor()` 返回 `{ forceClose() }` 句柄；与 `closeActive()` 的差别写进 JSDoc（前者针对特定会话，后者针对"当前活动"）。
- 清理收敛到单一 `dispose` 闭包，重复 open 不叠加监听（测试断言 3 次 open = 3 次 add / 3 次 remove）。
- `MTextInputBox` 构造失败时返回 `Promise.resolve(null)` 而非抛出，并释放隐藏工具条宿主。

### 3.2 取消路径不再写库（B1，高危）

**问题**：真实库 `@mlightcad/mtext-input-box` 的 `closeEditor()` **同步** `emit('close')`，于是编辑器自己的 `onClose` 先把 Promise 解析成完整结果，随后的 `finishSession(null)` 被 `finished` 守卫吞掉 → 按 Esc / 切图取消反而 `appendEntity` 创建实体。

**修法**：新增 `cancelSession(session)`：先 `session.cancel()`（置取消标志并 `off('close', onClose)`），再 `closeEditor()`，最后 `finishSession(session, null)`；提交侧改为 `queueMicrotask` 延迟一拍，让同一 tick 内的取消获胜。

### 3.3 Esc 真正取消（B7，含两个高危回归的收尾）

`close` 事件无法区分"Esc"与"点击框外"，因此编辑器在 **capture 阶段**监听 `window` keydown，抢在库的 window handler 之前按取消结算。踩到并修掉的两个回归：

- **IME 组字态**：补 `if (event.isComposing || event.keyCode === 229) return`（与库 `viewer.js:763` 及仓库其它 6 处 Esc 处理点一致），避免中文输入法组字时按 Esc 丢弃整段文字。
- **焦点作用域**：按库 `viewer.js:136-145` 的语义补 `defaultPrevented` 与 `event.target` 判断——焦点在 `INPUT`/`TEXTAREA`/`SELECT`/contentEditable 且**不是本编辑器的隐藏 IME bridge**时不做取消。注意：库把隐藏 `<textarea>` 挂到 `document.body` 并聚焦，它才是真实按键目标，`view.canvas` 只是兼容分支；若只豁免 canvas 会让 Esc 完全失效。
- `window` 不存在的 headless 环境有守卫，不抛错。

### 3.4 创建路径宽度语义（B3）

编辑器排版宽度是 `max(1, width)`，命令侧此前没传 `committedWidth`，导致框宽 0 / 0.25 被写成 DXF 组 41 = 1。现命令侧用 `toCommittedWidth(width)` 显式传入（非有限或 ≤0 → 0，否则原值），"0 = 不换行"语义得以保留。

### 3.5 双击编辑不重复入场景（B2）

`editMTextEntity` 的 `finally` 此前无条件 `addEntity` 且 `!applied` 时又 `updateEntity`；`AcTrBatchedGroup` 对同一 objectId 是**累加**语义，于是取消编辑后文字与选择框被画两遍。现改为二选一：`applied ? addEntity : (updateEntity + isDirty)`。

### 3.6 销毁时关闭编辑器（B8）

`AcApDocManager.destroy()` 此前不关闭内联编辑器（`onBeforeOpenDocument()` 已有），导致宿主卸载时会话、window capture 监听、输入框与永不 settle 的 Promise 一起存活。现于 `destroy()` 首行调用 `closeActiveInlineEditor()`，且早于 `AcTrMTextRenderer.resetInstance()`。

### 3.7 渲染侧

- **B4**：`trimPendingGlyphKeys` 的触发条件与裁剪目标值原本共用 `keepCount`，声明上限 4096 实际只有 2048；现触发用 `MAX_PENDING_GLYPH_KEYS`、目标用其一半，重复标注的晋升窗口恢复为声明值。
- **B5**：`recordPrintableCharMisses` 把廉价早退（已上报字体、节流窗口、条目上限）提到 `toLowerCase()` / `Date.now()` 之前，减少 MTEXT 热路径上的分配与时钟读取。
- **B6**：`AcTrRenderer` 字体诊断桥原为每实例订阅（页面级 `FontManager.instance` 永不重置，每次开图累加监听）；改为模块级一次性桥 + 迁移 MTEXT 单例监听，`AcTrMTextRenderer` 自身的 fontLoaded/fontNotFound 订阅也在 `dispose()` 解绑。
- **P3-5**：`clonePlacedMTextTemplate` 的 box 按 `(新插入点 - 模板自身插入点)` 平移（基准取 `template.position`，因为 `box.min` 受附着点/旋转偏移），空或退化 box 跳过。

### 4.2 负控（证明测试真的能抓住回归）

修复前先让 mock 忠实于真实库（`closeEditor()` 同步 emit `close`），拿到 5 条**预期红灯**：取消写库（2 条）、组 41 宽度 0.25/0（2 条）、pending 上限 2048≠4096（1 条）。修复后同一批断言全绿。

终验阶段又做了 6 组变异实验，每次都在临时副本上进行并已删除、基线 SHA256 校验一致：

- 删掉 IME 守卫 → 恰好 2 条组字态用例变红；
- 中和 target 守卫 → 恰好 4 条外部输入框用例变红（IME 目标与 canvas 取消仍绿）；
- 让假 window 的解绑失效 → 3 条"监听已释放"断言变红（含 capture 阶段断言）；
- 改坏 destroy 断言期望值 → 按预期失败；
- 重命名私有 `imeInput` 读取 → 恰好"从编辑器自身 IME textarea 取消"这条变红（证明它是对该私有字段的探测器）；
- 移除 Escape 结算 → Escape 用例变红（超时未 settle）。

## 5. 已知局限与风险

1. **未做真实浏览器验证**：IME 候选窗 Esc、工具条字体/字号控件 Esc、命令行输入框 Esc 均只用结构化替身断言，未在浏览器实测（jest 为 node 环境）。
2. **依赖库私有字段**：豁免本编辑器 IME 目标依赖 `mtext-input-box` 的私有运行时字段 `imeInput`；该依赖升级后需重跑"从编辑器自身 IME textarea 取消"这条用例。
3. **jest 退出码抖动**：首跑偶发 all-pass 但 exit 1（`A worker process has failed to exit gracefully`），复跑 exit 0；CI 若以退出码为门禁需注意。
4. **`target !== view.canvas` 分支未被测试区分**：真实 DOM 中 `<canvas>` 本就不属于原生可编辑元素，属防御性代码。
5. **B6 无自动化测试**：仅代码走查验证；且桥只服务"最后构造的 renderer"，多 view 宿主需改为注册表。
6. **双击编辑的字高回退为既有行为**：`height <= 0` 的实体在双击编辑时会用 `pixelsToWorldY(24)` 写入 DXF 40（viewport 相关）。为本轮之前既有行为，已记录但未改——需要合约定夺"从文字样式解析"还是"保持不写"。
7. **工作区既有未提交改动**：本会话之前已有 30+ 文件改动（含 5 个文件被写入 UTF-8 BOM、`tr/jig.ts` 有引号风格漂移），提交前建议归位。
8. **`_pendingGlyphKeys` 瞬时峰值为上限 +1**（第 4097 个 key 入表后才裁剪），常量语义为"裁剪触发阈值"，注释已说明。
