# 样条拟合多段线打散产生重叠直线修复总结

- 日期：2026-09-04
- 涉及文件：`cad-tools/process_dxf.py`（DXF 批量预处理脚本，基于 ezdxf 1.4.4）
- 目标图纸：`cad/dxf/千树塔井上下对照图（2025.04）.dxf`（95MB；输出 `cad/dxf/processed/千树塔井上下对照图（2025.04）.dxf`）
- 关联文档：`../../cad-tools/process_dxf.md`（脚本详细文档，2.10 节已同步更新）、`../06-工具脚本/process_dxf处理逻辑分析.md`

## 1. 背景与现象

用户报告：`process_dxf.py` 解析《千树塔井上下对照图（2025.04）.dxf》中的等高线对象（示例如下两个句柄）后，打散会"多产生重叠的直线，除曲线转弯处"——即等高线平直段出现视觉重叠的重复线，而在曲线转弯处又能看到多余的直线斜穿。

| 句柄 | 图层 | 线型 | 示例点 (X, Y) |
| --- | --- | --- | --- |
| B812D6 | 计曲线 | Continuous | 37415843.97654962, 4260064.143951919 |
| B9F1EA | DGX | Continuous | 37415839.0703354, 4260066.369176377 |

## 2. 诊断与根因

### 2.1 实体结构

两个对象都是**旧式 2D POLYLINE**，`flags = 133 = 1(闭合) + 4(样条拟合) + 128(连续线型)`，即 AutoCAD 的 SPLINEFIT 多段线。该类实体同时存储两类顶点：

| 顶点 flag | 含义 | 数量(B812D6/B9F1EA) | 角色 |
| --- | --- | --- | --- |
| 8 | 样条顶点（spline vertex created by spline-fitting） | 40 | **真正的曲线采样点，AutoCAD 只绘制它们** |
| 16 | 样条框架控制点（spline frame control point） | 5 | 用户原始点击的控制多边形顶点，仅是 B 样条数据，**不参与绘制** |

顶点在文件中的存储顺序为：`C + 8888…(40个) + CCCC`——1 个框架控制点打头，40 个样条顶点，4 个框架控制点收尾。

### 2.2 几何验证：控制点是纯数据

样条顶点恰好落在框架边中点上（坐标精确到 6 位小数吻合）：

- B812D6：SP[1] = (CP0+CP1)/2 = (37415843.976550, 4260064.143952)；SP[9] = (CP1+CP2)/2 = (37415844.051434, 4260061.856262) ✓
- B9F1EA：SP[1] = (CP0+CP1)/2 = (37415839.070335, 4260066.369176) ✓

40 个样条顶点 = 5 条框架边 × 每边 8 个采样点，构成闭合二次 B 样条曲线。框架控制点仅决定曲线形状，AutoCAD 渲染样条拟合多段线时**不画**控制点连线。

### 2.3 打散代码的错误路径

`polylines_to_lines` 的处理链：

1. `polyline_straight_segments(e)` 发现 `flags & 6`（曲线拟合 2 / 样条拟合 4）→ 返回 `None`；
2. 回退到慢速路径 `path.make_path(e)` + `flatten_path_to_lines()`；
3. **问题所在**：ezdxf 1.4.4 的 `make_path` 对 POLYLINE 无差别地使用 `polyline.vertices` **全部**顶点按存储顺序连线（`converter.py` `_from_polyline`：`points = [vertex.format("xyb") for vertex in polyline.vertices]`），没有任何样条拟合特殊处理。

于是每个对象被打散成 45 段 = **39 段正确的样条弦 + 6 段多余的框架连线**：

| 多余段 | 端点 | 性质 |
| --- | --- | --- |
| 1 | CP0 → SP1 | 控制点桥接段（1.7m 弦） |
| 2 | SP40 → CP1 | 控制点桥接段 |
| 3 | CP1 → CP2 | 框架多边形边 |
| 4 | CP2 → CP3 | 框架多边形边 |
| 5 | CP3 → CP4 | 框架多边形边 |
| 6 | CP4 → CP0 | 闭合框架边（8.5m 长弦） |

### 2.4 重叠现象的解释

在输出文件中逐段核实，6 段多余连线**全部真实存在**（6/6）。其中 B812D6 的闭合框架弦 CP4→CP0 与真实样条弦有 **1.02m 的部分重叠**（共线且区间重叠）。

由于这些多余线与真实样条弦是**部分重叠**（端点不同），"删除重复实体"阶段的 `fast_dedup_key`（按完整端点匹配）无法剔除它们，最终呈现为：

- 等高线平直段：框架弦贴着样条弦走 → 视觉上的"重叠直线"；
- 曲线转弯处：框架弦斜穿样条曲线 → 多余直线清晰可见。

### 2.5 影响范围

对源文件（模型空间 + 全部块定义）全量统计：

| 指标 | 数值 |
| --- | --- |
| 样条拟合多段线（flags & 4） | 771 条 |
| 真实样条顶点（flag & 8，应保留） | 225,555 个 |
| 框架控制点（flag & 16，应剔除） | 28,620 个 |
| 估计多余直线段 | 约 29,000 条 |

曲线拟合多段线（flags & 2）在本文件中为 0 条，未涉及。全文件 flag & 8 顶点均无凸度（bulge = 0），直线连线是精确做法，不存在离散误差问题。

## 3. 修复方案

**原则**：样条拟合多段线只取 flag & 8 的样条顶点作为几何，框架控制点（flag & 16）是数据不是几何，一律剔除。修复只影响 `flags & 4` 的旧式 2D POLYLINE，纯直线、凸度弧、3D 多段线路径完全不变。

`cad-tools/process_dxf.py` `polyline_straight_segments` 改动：

```python
def polyline_straight_segments(e):
    """POLYLINE 无凸度/无曲线拟合时直接返回线段; 否则返回 None 走 path 慢速路径"""
    if e.is_3d_polyline:
        pts = [v.dxf.location for v in e.vertices]
    elif e.is_2d_polyline:
        if e.dxf.flags & 4:  # 样条拟合: 只取样条顶点(flag&8), 框架控制点(flag&16)不是几何
            pts = [v.dxf.location for v in e.vertices if v.dxf.get("flags", 0) & 8]
            if not pts:
                return None
        elif e.dxf.flags & 2:  # 曲线拟合(2)需走慢速路径
            return None
        else:
            pts = []
            for v in e.vertices:
                if v.dxf.bulge:
                    return None
                pts.append(v.dxf.location)
    else:
        return None  # 多面网格等
    if e.is_closed and pts:
        pts.append(pts[0])
    return [(a, b) for a, b in zip(pts, pts[1:]) if not a.isclose(b, abs_tol=EPS)]
```

改动要点：

1. `flags & 6` 整体判断拆分为 `flags & 4`（样条拟合）与 `flags & 2`（曲线拟合）两条分支；
2. 样条拟合分支只收集 `flag & 8` 顶点，闭合多段线按原有逻辑补回起点；
3. 顶点列表为空（异常数据）时返回 `None`，回退到原有慢速路径，保证鲁棒性。

**闭合缺口说明**：样条顶点是等间隔采样（每边 8 点），最后一个样条顶点与第一个之间留有约 1/8 边长的采样缺口（B812D6 为 0.45m，B9F1EA 为 1.64m）。闭合补回的弦段是对该段真实 B 样条弧的近似，弦高误差可忽略。

## 5. 注意事项与遗留

1. **存量输出需重跑**：本次仅重新解析了 2025.04 这一张图，`cad/dxf/processed/` 下其他文件的旧输出仍含同样问题，建议全量重跑 `process_dxf.py`。
2. **曲线拟合多段线（flags & 2）未覆盖**：本文件中该类型为 0 条，其顶点排布与 `make_path` 的处理正确性未经实测验证。若其他图纸出现同类现象（PEDIT Fit 曲线），需按相同思路排查——曲线拟合多段线中 flag & 1 的拟合顶点才是几何，flag 为 0 的原始控制顶点需确认存储顺序后再决定是否剔除。
3. **样条顶点带凸度的罕见情况**：本次全文件 22.6 万个 flag & 8 顶点凸度均为 0。若遇到带凸度的样条顶点（非标准文件），当前实现会按直线处理；可扩展为在样条顶点存在凸度时走 path 慢速路径（并在慢速路径中同样只取 flag & 8 顶点构造 path）。
4. **排查工具**：本次诊断与验证脚本保留在 `cad-tools/tools/` 下，`probe_b812d6.py`（实体结构）、`probe_b812d6_verts.py`（顶点序列）、`probe_b812d6_overlap.py`（重叠量化与输出核对）、`probe_splinefit_stats.py`（全文件统计）、`probe_splinefit_fix.py`（修复方案预验证）、`verify_splinefix.py`（修复后输出验证），可复用于同类问题的排查。
