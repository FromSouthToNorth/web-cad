# 「读取巷道」初次点击无反应 — 根因分析与修复总结（本仓库落地版）

- 日期：2026-09-10
- 涉及仓库：`cad-viewer`（`cad-tunnel-plugin` + `cad-viewer-example` Ant Design 壳）
- 关联文档：`cad-viewer/packages/cad-tunnel-plugin/README.md`、`cad-viewer/packages/cad-tunnel-plugin/docs/绘制巷道插件设计.md`、`docs/05-使用手册/绘制巷道插件使用说明.md`
- 现象：打开大图纸（如 94MB 千树塔 DXF）期间/之后，第一次点击功能区「读取巷道」无任何反应，**再点一次才出图**；空图纸场景偶发第一次点击报「当前没有打开的图纸文档」

## 0. 与原总结的差异（宿主已迁移，fix #1 改写位置）

原始总结的 fix #1 针对的宿主是 Element Plus 时代的 `MlRibbonCommands.vue`（`[data-group-id]` / `[data-item-id="cmd-qselect"]` DOM 契约，插件 `ribbonButton.ts` 克隆注入）。该壳已于 `809e4fe`（2026-09-03，「删除旧 Element Plus 壳与 /legacy 子路径，element-plus 完全退出依赖」）删除；当前宿主是 `cad-viewer-example` 的 Ant Design 壳，功能区为声明式模型（`ribbonModel.ts`），「读取巷道」是宿主原生按钮（`utilities` 面板 small 项，藏在面板标题下拉里）。

因此：

- **fix #1** 在本仓库按同等思路改写到 **antd 壳**（视觉禁用 + 点击排队重放），而不是改写插件注入代码；
- 插件 `ribbonButton.ts`（及 `cad-invertsel-plugin/src/ribbonButton.ts` 的同构模块）在本仓库已无匹配宿主 DOM，是死代码，本次**不修改**；
- **fix #2**（命令层等待文档就绪）按原设计**原样落地**。

## 1. 结论

两个独立问题叠加，都在「图纸打开窗口期」内触发：

1. **宿主禁用态是原生 `disabled`，第一次点击被浏览器直接吞掉**。`AntdRibbon.vue` 把功能区整体禁用态定义为 `disabled = props.disabled === true || isDocumentOpening.value`，面板/QAT/下拉按钮把它直接绑定到真实 `<button>` 的 `:disabled`。原生 `disabled` 的按钮不派发任何 click 事件，点击静默丢失——这就是「初次无反应」的直接原因。
2. **命令执行时文档尚未就绪，直接报错返回**。即使点击到达命令层，`drawtunnel`/`tunnelclear` 在 `curDocument` 为 null（插件注册与文档激活并发）时立即 `log.error` 退出，不再重试。

## 2. 根因分析

### 2.1 原生 disabled 吞掉点击（antd 壳）

宿主禁用链：

```ts
// AntdRibbon.vue
const disabled = computed(
  () => props.disabled === true || isDocumentOpening.value
)
```

`isDocumentOpening` 来自 `useDocument()`：`documentToBeOpened` 时置 true、`documentActivated` 时置 false。打开 94MB 大图期间功能区全部按钮处于禁用态，而三个组件把该状态**物理同步**到原生属性上：

```html
<!-- AntdRibbonPanel.vue（简单按钮 / 面板标题下拉） -->
<button :disabled="props.disabled" ...>
<!-- AntdQat.vue -->
<button class="antd-qat-btn" :disabled="props.disabled" ...>
<!-- AntdDropdownButton.vue -->
<a-dropdown :disabled="props.disabled"><button :disabled="props.disabled" ...>
```

原生 `disabled` 的按钮在浏览器里**根本不会产生 click 事件**（连捕获都不会），`run()` 里的 `if (disabled.value) return` 守卫成了死代码。「读取巷道」是 small 项、位于面板标题下拉菜单内：打开期间第一步点击连菜单都打不开。

### 2.2 文档未就绪时命令直接失败（`AcApDrawTunnelCmd` / `AcApTunnelClearCmd`）

插件注册是异步的（`registerTunnelPlugin` 动态 import + `loadPlugin`），按钮出现瞬间文档可能仍在创建/打开中。旧命令代码：

```ts
const doc = AcApDocManager.instance.curDocument
if (!doc) {
  log.error(`[cad-tunnel] ${tunnelT('draw.noDocument')}`)  // 直接放弃
  return
}
```

只要点击落在 `curDocument === null` 窗口内，命令立刻失败且无重试——与 2.1 叠加后，「初次点击」几乎必挂。

## 3. 修复（本仓库实际落地）

### 3.1 antd 壳：视觉禁用 + 点击排队重放（fix #1 的等价物）

**新增 `cad-viewer-example/src/shell/ribbon/commandQueue.ts`（`CommandQueue`）**：

- `enqueue(command)`：未阻塞时立即执行；阻塞时入队（`Set` 去重，同一按钮连点只执行一次），返回「是否新入队」供提示判断；队列 0→1 时绑定文档生命周期监听；
- `scheduleFlush()`（绑 `documentActivated`，或阻塞解除后调用）：150ms 后重放（先给宿主一帧重新启用功能区的时间）；重放前仍阻塞则 300ms 定时重试，上限 200 次 ≈ 60s，防挂死；
- `dropPending()`（绑 `failed-to-open-file`）：清空队列，避免把巷道画进上一张图/错误图纸；
- 队列清空即解绑监听；`dispose()` 供组件卸载时清理定时器与监听。

**组件改造**：

- `AntdRibbon.vue`：`run()` 改为经队列分发；新入队时经 `eventBus` 发一条 `message` 提示（`shell.ribbon.commandQueued`）；`watch(disabled)` 在阻塞解除且队列非空时补一次 flush（编辑器启动的 `props.disabled` 门没有文档事件）；`onBeforeUnmount` 时 `dispose()`。
- `AntdRibbonPanel.vue` / `AntdDropdownButton.vue` / `AntdQat.vue`：按钮不再绑原生 `:disabled`，改为 `is-disabled` 类 + `aria-disabled`（视觉禁用、无障碍语义保留）；移除各自的 `if (props.disabled) return` 守卫，点击全部流向 `run()`；面板标题下拉在打开期间保持可打开（small 命令如「读取巷道」在菜单里）。QAT 改为向上 emit 命令，与面板共用同一条排队路径。
- `shell.css`：`:disabled` 选择器扩展为 `:disabled, .is-disabled`（`antd-qat-btn`、`antd-ribbon-panel-title--dropdown`、`antd-ribbon-button--large`、`antd-ribbon-button--small`）。
- 提示文案：`locale/zh.ts`、`locale/en.ts` 新增 `shell.ribbon.commandQueued`（壳仅 zh/en 两个语言文件）。

**范围说明**：`AntdLayerSelect` / `AntdPropertyBar` / 状态栏仍是真实 `disabled`（它们不是命令分发控件，点击后直接改状态，本次不动）。

### 3.2 插件：新增 `command/waitForDocument.ts` + 命令兜底（fix #2 原样落地）

```ts
export async function waitForCurrentDocument(timeoutMs = 60000): Promise<AcApDocument | null>
```

- 轮询 `AcApDocManager.instance.curDocument`（200ms 间隔，最长 60s）；
- 监听 `failed-to-open-file` 早退；返回 null 才走原「无文档」报错路径。

`AcApDrawTunnelCmd` / `AcApTunnelClearCmd` 均改为：先 `await waitForCurrentDocument()` 再操作数据库。此兜底同时覆盖命令行直接敲 `drawtunnel` 的场景。

## 5. 遗留与说明

1. **交互差异（有意为之）**：打开期间按钮呈 `is-disabled` 视觉样式但仍可点击，点击会被排队而非拒绝——与 AutoCAD「禁用即拒绝」的交互不同。这是为了兑现「第一次点击就生效」；若产品侧要求完全一致，可回退为「禁用 + 弹提示」（删掉排队、恢复 `run()` 守卫）。
2. **修复作用于整个功能区**：所有命令按钮（含 QAT、下拉按钮）共用排队路径，不只巷道。
3. **插件注入代码未动**：`cad-tunnel-plugin/src/ribbonButton.ts` 与 `cad-invertsel-plugin/src/ribbonButton.ts` 面向旧 Element Plus 宿主（`@mlightcad/ribbon`）的 DOM 注入在本仓库是死代码（无匹配的 `data-group-id` DOM）；若将来宿主回归该契约，需按原总结的 fix #1 思路（`pendingActivations` 队列）在这两个文件里补做点击排队。
4. **回归要点**：宿主 Ribbon 结构调整（`ribbonModel` 面板/按钮增删、禁用链变化）时，回归路径 = 打开大图纸期间点击「读取巷道」→ 应出现排队提示 → 图纸打开完成后巷道自动绘制。
