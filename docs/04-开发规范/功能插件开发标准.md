# 功能插件开发标准

- 日期：2026-08-27
- 适用范围：本仓库中基于 `@mlightcad/cad-simple-viewer` / `@mlightcad/cad-viewer` 的 CAD 查看器，后续所有**功能性插件**（命令、快捷键、Ribbon 按钮、面板等）的开发
- 参考实现：[`cad-viewer/packages/cad-invertsel-plugin`](../../cad-viewer/packages/cad-invertsel-plugin)（反选插件，本标准的首个完整案例，其包内 `docs/` 含逐文件的实现细节）

本标准是后续插件功能开发的公共参考。目标是：**新功能以插件形态交付，`cad-simple-viewer` / `cad-viewer` 两个库包源码零改动**，与上游 `mlightcad/cad-viewer` 保持可合并性；插件可整包增删而不留痕迹。

---

## 1. 设计原则

1. **库源码零入侵**：功能代码（命令类、视图方法、快捷键分支、Ribbon 项、语言条目、图标）一律不进库包。库包只允许使用既有的公开扩展点；若某能力确实需要库提供新扩展点，必须做成**通用机制**（与具体功能无关），并单独评审——禁止把功能专用代码写进库
2. **功能全内聚**：一个功能的全部资产（逻辑、命令、UI、文案、图标、测试）都在自己的插件包内
3. **只用公开 API**：插件仅依赖 `cad-simple-viewer` 的公开导出（`AcApDocManager`、`AcApPlugin`、`AcEdCommand`、`AcApI18n`、视图/编辑器/选择集等公开访问器）。不得 import 库的内部路径，不得修改原型链或私有成员
4. **应用层接线**：插件的注册调用写在**应用**（如 `cad-viewer-example` 或实际产品应用）的初始化代码里，与应用自有命令（如 `quit`/`exit`）同一位置。库层的 `register.ts` / `registerLazyPlugins` 不为新插件改动

## 2. 何时做成插件（决策）

| 功能特征 | 建议 |
| --- | --- |
| 自有命令/按钮/快捷键，可被移除而不影响其他功能 | **做成插件**（本标准） |
| 重度依赖库内部实现、需新增大量库侧钩子 | 先评估是否应向上游提通用扩展点，再插件化 |
| 修正库的缺陷、改进既有行为 | 属于库的修改，不做插件（直接改库并补 changeset） |

## 3. 包骨架（模板）

新插件放在 `cad-viewer/packages/cad-<feature>-plugin/`，复制参考实现的四个配置文件后改包名：

```
cad-<feature>-plugin/
├─ package.json            name 用 @mlightcad/cad-<feature>-plugin；private: true；
│                          peerDependencies + devDependencies: cad-simple-viewer（必要时加 data-model）
├─ tsconfig.json           extends ../../tsconfig.json；rootDir src / outDir lib；paths 自映射
├─ vite.config.ts          双入口（index + register）；peerDepsExternal；external 含自身包名
├─ project.json            nx 目标 build/lint/clean，build dependsOn ^build
├─ README.md               用法与速览，链接到 docs/ 下的详细文档
├─ docs/                   功能级详细文档（设计、机制、限制、回退清单）
└─ src/
   ├─ index.ts             公共导出（插件类、工厂、常量）
   ├─ register.ts          ★ 注册入口——只允许常量 + 类型导入 + 动态 import 主包
   ├─ create<Feature>Plugin.ts  异步工厂
   ├─ AcAp<Feature>Plugin.ts    插件类（生命周期装配点）
   └─ …                    功能模块（命令/逻辑/快捷键/UI 注入/i18n）
```

## 4. 加载策略（二选一，建包时确定）

| 策略 | 适用 | 做法 |
| --- | --- | --- |
| **急切加载** | 有快捷键、常驻按钮/面板等**首次交互前必须就位**的能力 | `register.ts` 导出 `register<Feature>Plugin(pluginManager)`：`await import(主包)` 后立即 `pluginManager.loadPlugin(...)`；先 `isPluginLoaded` 防重 |
| **触发懒加载** | 重资源、按需能力（导出/转换类） | 参考 `cad-svg-plugin`：`pluginManager.registerLazyPlugin({ name, triggers: [命令名], loader })`，用户首次在命令行触发命令时才下载插件包 |

无论哪种：`register.ts` 都保持独立 `/register` 子路径导出（package.json `exports` 双入口），使插件主包不进应用首屏 chunk。**注意**：`register.ts` 内不得静态引入主包模块，否则拆分失效。

## 5. 标准机制

### 5.1 命令注册

- `onLoad(context, commandManager)` 中 `commandManager.addCommand(AcEdCommandStack.SYSTEMT_COMMAND_GROUP_NAME, '<name>', '<name>', new XxxCmd())`；`onUnload` 中 `removeCmd` 对称清理
- 命令类 `extends AcEdCommand`，`execute(context)` 实现逻辑；命令行、Ribbon 按钮等入口统一走 `AcApDocManager.instance.sendStringToExecute('<name>')`，保证单一路径与 CLI 回显
- 需要用户输入的命令用 `context.editor` 的输入采集 API；纯动作命令直接执行

### 5.2 视图与选择集（常用公开 API）

- `AcApDocManager.instance.curView`：当前 `AcTrView2d`（事件时动态读取，不要缓存，文档重建后自动正确）
- `view.editor.selectAll(filter?)`：模型空间候选集；`view.selectionSet`（`has/add/delete/clear/count` + `events.selectionAdded/Removed`）
- 事件顺序约定：选择集变更先派发 `selectionAdded` 再 `selectionRemoved`；诊断日志沿用 `[cad-selection]` 前缀格式，便于与宿主日志对照

### 5.3 快捷键

插件自持 `document` 级 `keydown` 监听（冒泡阶段），守卫必须与宿主 `AcEdViewKeyHandler` 保持一致：

| 守卫 | 处理 |
| --- | --- |
| `e.isComposing` / `e.keyCode === 229`（IME） | 忽略 |
| 目标为 `TEXTAREA` / `contentEditable` / 普通 `INPUT` | 忽略 |
| 目标为命令行输入框 `.ml-cli-text` | 仅当值为空且非只读时放行 |
| `AcEdMTextEditor.getActiveInputBox()` 非空 | 忽略 |
| `view.editor.isActive`（命令采集中） | 忽略 |

键位判定用 `e.code`（物理键位）+ `ctrlKey || metaKey` 兼容 macOS。监听器在 `onUnload` 中摘除，start/stop 幂等。

### 5.4 Ribbon 按钮（DOM 注入方案）

宿主 Ribbon（`@mlightcad/ribbon` + `MlRibbonCommands.vue`）目前**没有扩展点**，按钮模型在组件内部构建。在库保持零入侵的前提下，标准做法是 DOM 注入（完整实现见参考实现 `ribbonButton.ts`）：

1. `MutationObserver`（body 级 `childList+subtree`）在元素增删批次后执行一次 `ensure`
2. `ensure`：定位目标组 `[data-group-id="<组id>"]` → 已注入则跳过 → 否则深克隆组内一个同尺寸现有按钮（如 `[data-item-id="cmd-qselect"]`）作为模板，改写 `data-item-id`/`data-ribbon-button-id`、替换 `.ml-ribbon-button__label` 文案与 `.ml-ribbon-item-host__icon` 内联 SVG 图标、挂点击监听（走命令管线），插入模板之后
3. 自愈：宿主重渲染（语言切换/标签切换/响应式折叠展开）会丢弃注入节点，下一批 mutation 自动重注入
4. 禁用态：注入时镜像模板按钮的 `disabled`/`is-disabled`；点击时再实时校验一次模板按钮状态（功能兜底）
5. 图标用 `fill="currentColor"` 的内联 SVG，随主题变色

**该方案的固有边界**（须在插件文档中声明）：与 ribbon 包的内部 DOM 结构（`data-group-id`/`data-item-id`/class 名）耦合，宿主 ribbon 升级后必须回归验证；提示用原生 `title` 而非 el-tooltip；不参与窄宽折叠弹窗。若未来库提供了正式 Ribbon 扩展点，应迁移并废弃 DOM 注入。

### 5.5 多语言（i18n）

- 插件自带全部语言文案（当前宿主支持 en/zh/tr/cs），不改宿主任何语言文件
- **初始语言自行解析**，优先级与宿主 `useLocale` 一致：`localStorage['preferred_lang']` → 浏览器语言（tr/cs 特判）→ 默认 `zh`
  - ⚠️ 不要用 `AcApI18n.currentLocale` 当初始值：宿主启动时若语言来自 localStorage，不会同步进 `AcApI18n`（其默认 `zh`），会拿错
- 运行时切换：订阅 `AcApI18n.events.localeChanged`，回调里更新已注入 UI 的文案
- 可选：把文案 `AcApI18n.registerMessage(locale, { <plugin>: … })` 注册进宿主注册表，供他方 `AcApI18n.t()` 取用

### 5.6 宿主应用既有基建速查

| 能力 | 入口 |
| --- | --- |
| 插件管理 | `AcApDocManager.instance.pluginManager`（`loadPlugin/unloadPlugin/isPluginLoaded/getLoadedPlugins/registerLazyPlugin`） |
| 命令栈 | `AcApDocManager.instance.commandManager` / `AcEdCommandStack.SYSTEMT_COMMAND_GROUP_NAME` |
| 命令执行 | `AcApDocManager.instance.sendStringToExecute(name)` |
| 当前视图/文档 | `AcApDocManager.instance.curView` / `curDocument` |
| i18n 注册表 | `AcApI18n.registerMessage / t / events.localeChanged` |
| 对话框注册 | cad-viewer 的 `useDialogManager().registerDialog`（需库层已有该能力时再评估依赖方向） |

## 6. 开发工作流

```bash
# node/pnpm（Git Bash 下）
export PATH="/e/nodejs:/c/Users/bw/AppData/Local/pnpm:$PATH"

cd cad-viewer
pnpm install                                            # 新包首次：链接 workspace

# 构建顺序：插件 tsc 依赖 cad-simple-viewer 的 lib 类型产物
pnpm --filter @mlightcad/cad-simple-viewer build
pnpm --filter @mlightcad/cad-<feature>-plugin build
```

### 6.1 ⚠️ dev 模式别名（最易踩的坑）

`cad-viewer-example/vite.config.ts` 在 dev 模式把 `cad-simple-viewer`/`cad-viewer`/`cad-svg-plugin`/`three-renderer` 别名到**源码 src**；**新插件不在别名内**，经 node_modules 解析到自身 `dist/`：

- 改库源码 → dev 热更生效
- **改插件源码 → 必须重新 `pnpm --filter @mlightcad/cad-<feature>-plugin build` 才生效**

高频开发插件时可自行把插件加进 example 的 dev 别名（应用层改动，允许）。运行时单例一致性无需担心：插件将 `cad-simple-viewer` external，dev 下同样解析到 src，`AcApDocManager` 单例与宿主共享。

### 6.2 调试

- DEV 模式应用在 `window.AcApDocManager` 暴露文档管理器，控制台可直接读取插件加载状态、选择集计数等
- 注入的 Ribbon 节点用 `[data-item-id="cmd-<feature>"]` 自检

## 7. 验证标准（交付前必过）

1. `pnpm --filter @mlightcad/cad-<feature>-plugin lint` 无告警
2. `pnpm --filter @mlightcad/cad-simple-viewer build`、`pnpm --filter @mlightcad/cad-viewer build`（vue-tsc）通过——证明库侧无残留引用
3. `pnpm --filter @mlightcad/cad-viewer-example exec vue-tsc --noEmit` 通过——证明应用接线正确
4. `cd cad-viewer && npx jest`：功能相关套件通过（仓库现存 `packages/data-model` 若干套件因独立于插件的 TS 问题失败，属既有状态，不作为本次验收依据）
5. 浏览器手测：命令行触发、各 UI 入口、快捷键守卫（输入框/命令行非空抑制、空命令行放行）、语言切换、视口宽窄变化、文档打开中禁用行为
6. 若功能改动涉及库回退：`git diff <上游基线> -- <库文件>` 应为空

## 8. 发布与版本

- 内部插件一律 `"private": true`，不发 npm、不参与 changesets；库包零改动时也不需要 changeset
- 若插件未来要对库外发布，再去掉 `private` 并补 changeset 流程
