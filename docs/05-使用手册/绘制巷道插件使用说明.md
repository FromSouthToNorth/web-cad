# 绘制巷道插件使用说明

> 本文档详细说明 bw-cad-view 项目中「绘制巷道」插件（`@mlightcad/cad-tunnel-plugin`）的功能、
> 数据格式、实体映射、属性面板、设置面板、配置项与扩展方式。
> 整理时间：2026-09-07。代码位置：`cad-viewer/packages/cad-tunnel-plugin/`。

## 一、插件概览

「绘制巷道」是一个规划插件：**不解析任何 DWG/DXF 文件**，直接从 GeoJSON 数据（HTTP 请求返回，
例如 axios/fetch）在图纸中绘制自定义对象——点、线（巷道中心线）、面（闭合多段线 + 填充）、
文字标注，并支持煤矿业务中的**特殊巷道类型**（立井、煤仓）符号化。

功能清单：

| 功能 | 说明 |
| --- | --- |
| 数据绘制 | `drawtunnel` 命令从配置 URL 拉取 GeoJSON，绘制点/线/面/文字 |
| 特殊巷道类型 | `tunnelType` 1/2/9/15 绘制立井符号，3 绘制煤仓符号（详见[五、特殊巷道类型](#五tunneltype-特殊巷道类型)） |
| 名称标注 | 按巷道名称自动标注，默认字号随数据范围自适应，并做碰撞避让 |
| 属性面板 | 选中实体后展示巷道业务属性（名称/类型/煤层/立井坐标等），可编辑并随 DXF 往返 |
| 设置面板 | Ribbon「巷道设置」按钮：巷道线宽、名称大小、碰撞避让，控件变化即防抖自动应用 |
| 清除命令 | `tunnelclear` 按巷道图层批量删除插件绘制的全部对象 |
| 语言 | 界面文案支持 zh / en / tr / cs 四种语言 |

插件源码结构：

| 文件 | 职责 |
| --- | --- |

| `src/entity/ShaftRoadway.ts` | 立井自定义实体（双圆 + 直径线符号） |
| `src/entity/CoalBunker.ts` | 煤仓自定义实体（立井符号 + 竖向刻度线） |
| `src/labelCollision.ts` | 标签宽度估算与碰撞贪心算法 |

## 二、安装与启用

插件是 pnpm 工作区私有包，应用侧通过 `/register` 子路径注册（急切加载：Ribbon 按钮必须在
首次交互前就位）：

```typescript
// cad-viewer-example/src/App.vue
import { registerTunnelPlugin } from '@mlightcad/cad-tunnel-plugin/register'

void registerTunnelPlugin(AcApDocManager.instance.pluginManager, {
  url: `${import.meta.env.BASE_URL}geojson/tunnel.json`
})
```

`registerTunnelPlugin(manager, options)` 的第二个参数即插件配置（见[十、配置项参考](#十配置项参考-tunneldrawoptions)），
在插件 `onLoad` 时写入插件模块状态，`drawtunnel` 命令运行时读取。注册后：

- 命令行新增 `drawtunnel`（别名 `tunnel`）与 `tunnelclear` 两个命令；
- Ribbon「实用工具」分组新增「绘制巷道」「巷道设置」两个按钮；
- 三个自定义实体类型（`TUNNELROADWAY` / `SHAFTCIRCLE` / `COALBUNKER`）注册进 DXF 自定义实体注册表。

## 三、快速上手

1. 点击 Ribbon「绘制巷道」按钮，或在命令行输入 `drawtunnel` / `tunnel`；
2. 插件从配置的 URL 拉取 GeoJSON 数据，解析并转换为实体，经事务批量入库（可一步撤销）；
3. 完成后自动缩放到全图，命令行输出绘制统计（对象总数、点/线/面/立井煤仓/文字分类数量）；
4. 点击 Ribbon「巷道设置」打开设置面板，调整线宽/名称大小/碰撞避让即实时生效（防抖合并为一次可撤销事务）；
5. 需要重绘时先执行 `tunnelclear` 清除旧对象，再重新 `drawtunnel`。

日志均带 `[cad-tunnel]` 前缀，便于在控制台过滤。

## 四、数据格式

### 4.1 支持的结构

`parseTunnelGeoJson` 兼容以下 JSON 形态：

1. 标准 GeoJSON `FeatureCollection`；
2. 单个 `Feature` 或单个几何对象；
3. `Feature` 数组；
4. 业务信封 `{ data: { params: { data: <FeatureCollection> } } }`（仓库 `GeoJSON/tunnel.json` 的形状）；
5. `{ data: <FeatureCollection> }`。

几何类型支持：`Point` / `MultiPoint` / `LineString` / `MultiLineString` / `Polygon` /
`MultiPolygon` / `GeometryCollection`。`Multi*` 与 `GeometryCollection` 只对第一个子几何标注文字，
避免重复。

### 4.2 Feature 属性字段

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 巷道唯一标识（普通巷道展示在属性面板，立井/煤仓展示为「巷道id」） |
| `tunnelName` | string | 巷道名称：用作文字标注与属性面板「巷道名称」 |
| `tunnelType` | number / string | 巷道类型编号（见[五、特殊巷道类型](#五tunneltype-特殊巷道类型)）；数字与数字字符串均支持 |
| `coalbed` | string / number | 煤层编号，展示在属性面板「煤层」 |
| `color` | string | 该要素颜色（CSS hex 如 `#00ffff` 或颜色名）；缺省时用配置 `color` 兜底，再缺省用图层色 |
| `columns` | array | 业务接口附带字段，插件忽略 |

### 4.3 坐标与高程

- 坐标取 `[x, y]` 或 `[x, y, z]`；`z`（高程）默认**忽略**（`elevationMode: 'ignore'`，所有实体画在 Z=0 平面）。
  原因：2D 矿图语义，且相机深度带会裁剪 Z 超出约 ±500 的实体；
- `elevationMode: 'relative'` 时，`z` 减去数据中最小高程后保留相对高差；
- 立井线要素的高程另有语义：两端 Z 较高者为**井口**、较低者为**井底**（见 5.3）。

## 五、tunnelType 特殊巷道类型

| `tunnelType` | 实体 | 符号 | 属性面板分组 |
| --- | --- | --- | --- |
| 1、2、9、15 | `ShaftRoadway`（立井巷道） | 双同心圆 + 水平直径线 | 立井信息 |
| 3 | `CoalBunker`（煤仓） | 立井符号 + 4 条竖向刻度线 | 煤仓信息 |
| 其他（0、25、26…） | `TunnelRoadway`（普通巷道） | 宽度带状线（中心线 + 宽度参数，实心填充渲染） | 巷道信息 |

示例数据中 `tunnelType` 为 2 的「主立井」「副立井」与 15 的「回风立井」即按立井符号绘制。

### 5.1 立井符号（ShaftRoadway）

- 以**井底**为圆心绘制两个同心圆：内圈半径 `shaftRadius`（默认 **15**），外圈半径
  `shaftRadius + shaftOuter`（默认 **15 + 5 = 20**，`shaftOuter` 为外圈加宽）；
- 绘制过圆心的**水平直径线**（左端 `x - 半径`、右端 `x + 半径`）；
- 几何等价于参考实现（MxCAD `ShaftCircle.worldDraw` 的 circle1 + circle2 + line）。

### 5.2 煤仓符号（CoalBunker）

在立井符号基础上增加 **4 条竖向刻度线**：起点均匀分布在水平直径上（`x = 圆心 ± r/2`、`± r`），
终点位于圆上弧内侧 98% 处（`y = 圆心 + √(r² − Δx²) × 0.98`），落到水平直径上。

### 5.3 井口 / 井底确定规则

- **线要素**：取线段两端 Z **较高者为井口（top）、较低者为井底（bottom）**，圆心定在井底。
  生产数据中立井是"同 XY、不同 Z"的垂直线段（如主立井 `[[x, y, 939.5], [x, y, 315]]`），
  首尾顺序无关，按 Z 高低判定；
- **点要素**：没有深度信息，井口 = 井底（符号画在该点）；
- `MultiPoint` / `MultiLineString` 中每个子几何各生成一个符号。

### 5.4 标注与优先级

立井/煤仓的名称标注位于**外圈正上方**（外圈边缘再偏移 0.7 倍字高）；碰撞避让时其优先级
按外圈周长（`2π × (shaftRadius + shaftOuter)`）计算，与普通巷道按长度排序的规则一致。

## 六、实体与图层映射

| GeoJSON | 实体 | 默认图层 |
| --- | --- | --- |
| `Point` / `MultiPoint` | `AcDbPoint` | 巷道点 |
| `LineString` 且带 `tunnelType`/`tunnelName`/`coalbed` 属性 | `TunnelRoadway`（中心线 + 宽度 + 巷道属性） | 巷道线 |
| 其他 `LineString` / `MultiLineString` | `AcDbPolyline` | 巷道线 |
| `Polygon` / `MultiPolygon` | 闭合 `AcDbPolyline` + `AcDbHatch`（SOLID 填充） | 巷道面 |
| `Point` / `LineString` 且 `tunnelType` ∈ {1,2,9,15} | `ShaftRoadway`（立井） | 巷道点 |
| `Point` / `LineString` 且 `tunnelType` = 3 | `CoalBunker`（煤仓） | 巷道点 |
| `tunnelName` 非空（标注字段可配置） | `AcDbText` 居中标注 | 巷道文字 |

说明：

- 图层按需自动创建，可整层控制显隐；`tunnelclear` 即按这四个图层批量删除；
- 立井/煤仓符号放在「巷道点」图层（它们是点状符号）；
- 图层名可通过 `layerNames` 配置覆盖。

## 七、属性面板

选中实体后，属性面板在通用/几何分组之外展示插件业务分组：

**普通巷道（TunnelRoadway）——「巷道信息」分组**

| 属性 | 可编辑 | 说明 |
| --- | --- | --- |
| 巷道名称 | ✔ | 对应 `tunnelName` |
| 巷道类型 | ✔ | 对应 `tunnelType` |
| 煤层 | ✔ | 对应 `coalbed` |

**立井（ShaftRoadway）——「立井信息」分组 / 煤仓（CoalBunker）——「煤仓信息」分组**

| 属性 | 可编辑 | 说明 |
| --- | --- | --- |
| 巷道id | ✔ | 对应 `id` |
| 巷道名称 | ✔ | 对应 `tunnelName`（缺省时立井为「立井」、煤仓为「煤仓」） |
| 井底坐标 X / Y / Z | ✘（只读） | 井底点坐标 |
| 井口坐标 X / Y / Z | ✘（只读） | 井口点坐标 |

编辑即时生效；属性值随 DXF 往返（见[十二、DXF 持久化](#十二dxf-持久化与自定义实体)）。

## 八、设置面板

入口：Ribbon「实用工具」→「巷道设置」按钮（再次点击关闭）。面板为浮动窗口，停靠视口右上角。

| 控件 | 范围 | 说明 |
| --- | --- | --- |
| 巷道线宽 | 0.1 ~ 20，步长 0.1 | 应用到全部巷道实体宽度（`TunnelRoadway.width`） |
| 名称大小 | 0 ~ 20，步长 0.5 | 应用到全部巷道名称文字高度；**0 = 自动**（按当前名称分布范围重新推导） |
| 名称碰撞避让 | 开/关 | 开：重算并隐藏相互重叠的名称；关：全部名称显示 |
| 关闭 | — | 关闭面板 |

面板**实时响应**：任一控件变化后经约 300ms 防抖自动应用，连续调整（如拖动滑杆）合并为
**一次可撤销事务**（自动刷新视图），并把线宽/字号/碰撞选项持久化为插件默认值，后续
`drawtunnel` 沿用。每次自动应用后命令行输出修改统计（更新对象数、显示/隐藏名称数）。

## 九、名称标注与碰撞避让

- 标注字段默认取 `tunnelName`（`labelField` 可配置为其他属性名，`null` 关闭标注）；
- 标注位置：线取中点、面取顶点平均质心、点取点上方 0.7 倍字高、立井/煤仓取外圈上方；
- **自动字高**：按数据 2D 范围对角线 × **0.0035** 自适应（无有效范围时回退 2）；设置面板或
  `labelHeight` 配置可显式覆盖；
- **碰撞避让**（默认开启）：每个名称的包围盒按字宽估算——CJK 字符宽 = 1 × 字高、
  其他字符宽 = 0.55 × 字高，盒宽加 0.2 × 字高边距、盒高取 0.75 × 字高；按优先级
  （几何长度，长者优先；立井/煤仓为外圈周长）排序后贪心保留互不重叠的名称，其余隐藏；
- 碰撞为启发式估算（非像素级精确），且只做名称与名称之间的避让，不避让其他几何；
- 绘制与设置面板应用时都会输出隐藏名称数量日志（`draw.labelsHidden` / `panel.applyDone`）。

## 十、配置项参考（TunnelDrawOptions）

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `url` | — | 数据地址（HTTP(S) 或同源相对路径）；缺省时 `drawtunnel` 命令行提示输入 |
| `layerNames` | 巷道点/巷道线/巷道面/巷道文字 | 分类图层名覆盖（可只覆盖部分） |
| `labelField` | `'tunnelName'` | 文字标注取值的属性名；`null` 关闭标注 |
| `labelHeight` | 0（自动） | 文字高度（图纸单位）；0 按数据范围自动推导 |
| `labelCollision` | `true` | 名称碰撞避让；`false` 时全部名称都绘制 |
| `roadwayWidth` | 2 | 普通巷道实体宽度（图纸单位） |
| `shaftRadius` | 15 | 立井/煤仓符号内圈半径（图纸单位） |
| `shaftOuter` | 5 | 立井/煤仓符号外圈加宽（图纸单位） |
| `useRoadway` | `true` | 带巷道属性的线是否建 `TunnelRoadway`；`false` 时退化为多段线 |
| `fillPolygons` | `true` | 面是否加 SOLID 填充 |
| `elevationMode` | `'ignore'` | 高程处理：`'ignore'` Z 归零；`'relative'` 保留相对高差 |
| `fitView` | `true` | 绘制完成后是否缩放到全图 |
| `color` | — | 要素无 `color` 属性时的兜底颜色 |

配置示例（在 `registerTunnelPlugin` 时传入）：

```typescript
void registerTunnelPlugin(AcApDocManager.instance.pluginManager, {
  url: '/geojson/tunnel.json',
  labelField: 'tunnelName',
  labelHeight: 0,            // 自动字号
  labelCollision: true,
  roadwayWidth: 2,
  shaftRadius: 15,
  shaftOuter: 5,
  elevationMode: 'ignore'
})
```

## 十一、命令参考

| 命令 | 别名 | 行为 |
| --- | --- | --- |
| `drawtunnel` | `tunnel` | 从配置 URL（或命令行提示输入）拉取 GeoJSON 并绘制；完成后缩放到全图；只读文档不可用 |
| `tunnelclear` | — | 删除四个巷道图层上的全部对象（可 undo），用于重绘前清空 |

## 十二、DXF 持久化与自定义实体

| 实体 | DXF 记录 | 业务数据持久化 |
| --- | --- | --- |
| `TunnelRoadway` | `TUNNELROADWAY` | 子类标记 `AcDbRoadway` 之后，XDATA 应用名 `TUNNEL` 存 3 条 `1000`：名称、类型、煤层 |
| `ShaftRoadway` | `SHAFTCIRCLE` | 子类标记 `AcDbShaftCircle`；点位码 10/20/30（井口）、11/21/31（井底）、40（半径）、41（外圈）；XDATA 应用名 `SHAFT` 存 id、名称 |
| `CoalBunker` | `COALBUNKER` | 同立井（子类标记 `AcDbCoalBunker`，XDATA 应用名 `BUNKER`） |

限制：

- 仅 **DXF** 文本往返；二进制 DWG 读取分发不查自定义实体注册表；
- 未加载本插件时读入上述记录，业务属性（XDATA）静默丢失，实体按代理实体处理；
- 未加载插件时导出的 DXF 中，这三个记录按代理实体写出。

## 十三、常见问题（FAQ）

**Q1：重绘后旧对象还在？**
插件不清除旧数据（幂等性留给业务侧），重绘前先执行 `tunnelclear`。

**Q2：有些巷道名称没显示？**
名称碰撞避让默认开启，重叠的名称按优先级隐藏。可在设置面板关闭「名称碰撞避让」、
调小名称字号，或放大视图查看。隐藏数量会输出在命令行日志。

**Q3：立井符号太小/太大？**
符号半径由 `shaftRadius`（内圈）+ `shaftOuter`（外圈加宽）决定，在注册插件时传入；
与自动字号（数据对角线 × 0.0035）无关。

**Q4：属性面板中巷道类型为空？**
旧版本只接受字符串 `tunnelType`；当前版本同时支持数字与数字字符串（如 `2`、`"2"`）。
确认插件已更新并重新 `drawtunnel`。

**Q5：高程没有体现？**
默认 `elevationMode: 'ignore'`（Z 归零，2D 矿图语义）。需要相对高差时配
`elevationMode: 'relative'`（注意相机深度带限制，仅适合相对高差 < 约 500 的场景）。

**Q6：数据拉取失败？**
检查 URL 是否同源/允许 CORS、返回结构是否为[四、数据格式](#四数据格式)支持的形态；
错误详情会以 `[cad-tunnel]` 前缀输出到控制台。
